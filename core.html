Chapter 01 · Core & Microarchitecture

核心微架構：計算、匯流排與記憶體保護

在車用電池管理系統（BMS）中，微控制器必須在極低待機功耗與嚴苛即時中斷之間取得完美平衡。以 Infineon PSoC™ 4 HVPA-144K 為例，其採用 32-bit Arm® Cortex®-M0+ 為運算核心，整合 8 通道 DMA 控制器、單層 AHB-Lite 系統互連矩陣，以及全晶片具備 SECDED 硬體糾錯功能的 Flash 與 SRAM 記憶體架構。

1. Arm Cortex-M0+ 處理器核心深度解析

傳統 8-bit 或 16-bit 車用微控制器在處理 32-bit 浮點濾波或 16-bit $\Delta\Sigma$ 高精度積分散熱計算時，需要消耗大量時脈週期。PSoC 4 HVPA 採用 Arm Cortex-M0+，運行時脈達 24 MHz 至 48 MHz，具備極高的能效比（達 2.46 CoreMark/MHz）。

2. 系統互連拓撲：AHB-Lite 與 DMA 控制器

車載類比感測需要以數 kHz 至數百 kHz 的高採樣率連續採集分流器電流波形。如果每次 ADC 轉換完成都透過中斷喚醒 CPU 讀取，處理器將被中斷淹沒。PSoC 4 HVPA 建立了單層 32-bit AHB-Lite 主幹匯流排與 APB 周邊橋接架構，並配置了 8 通道直接記憶體存取控制器（DMA）。

DMA 描述符鏈接機制 (Descriptor Chaining)

DMA 控制器支援散佈/聚集（Scatter-Gather）鏈結傳輸模式。當類比子系統 PACSS 完成一組雙通道（電流 + 電壓）採樣後，發出硬體觸發信號，DMA 即可自動將 32-bit 資料從 ADC 結果暫存器搬移至 SRAM 雙緩衝區（Ping-Pong Buffer），全程無需 CPU 參與，CPU 可持續處於低功耗 Sleep 模式，直到累積 100 筆資料後才產生一次中斷進行批次計算。

3. 記憶體子系統與 SECDED 硬體糾錯 (ECC)

車載環境中，高能宇宙射線中子與封裝材料中的微量放射性同位素（如釷、鈾釋放的 $\alpha$ 粒子）會引發單粒子翻轉（Single Event Upset, SEU）。如果 SRAM 內的電池電壓或電流標定值被竄改，將導致 BMS 誤判斷路。

單錯修正、雙錯檢測 (SECDED Hamming Code) 檢查位元公式：
若資料寬度為 \(k = 32\) 位元，所需校驗位元 \(p\) 必須滿足：
\[2^p \ge k + p + 1 \implies 2^6 = 64 \ge 32 + 6 + 1 = 39 \quad (p = 6 \text{ 位元用於單錯修正})\] 額外增加 1 個全體同位檢查位元（Parity Bit），總共需要 \(p = 7\) 位元校驗碼（Check Bits），即可達成 SECDED。

Flash 與 SRAM 的雙重防護機制

  • 128 KB Code Flash + 8 KB Data Flash： 內建硬體 ECC 產生器，每 64-bit 資料附加 8-bit ECC。讀取時硬體單週期透明解碼修正。若發生單一位元錯誤，硬體即時修正並累計至警示暫存器；若發生雙位元錯誤，硬體立即拉高非遮蔽中斷（NMI），阻止執行非法指令。
  • 8 KB SRAM ECC 防護： 每一筆寫入操作同步計算校驗碼寫入 ECC RAM，讀取時由硬體 SECDED 邏輯自動校驗。同時提供錯誤注入暫存器（Fault Injection Register），供安全診斷軟體在開機自我檢測（POST）期間手動翻轉位元，以驗證安全中斷機制是否完好。

4. 時脈樹與系統資源 (SRSS) 低功耗模式
